“Every factory runs on the same three things: a paper register, a payroll spreadsheet, and someone doing the OT math by hand at month-end.”

Attendance gets marked on paper. Payroll gets worked out on a spreadsheet only one person really understands. Advances get lent out on trust and half-remembered by payday. And when a worker questions a deduction, there's nothing to point to except “trust me.”

ClearWage puts all three in one place — attendance, payroll, and the advance ledger, on a phone instead of a register. Workers can check their own attendance and pull their own payslip instead of asking the office. And because it runs on your own server, none of it depends on a subscription you could lose access to.

A day with ClearWage

What actually changes for the person marking attendance, and the person waiting on their payslip.

For the owner / admin

Morning roster to month-end payroll

  • Mark — Bulk-mark the day's roster in a couple of minutes; OT and holidays are worked out automatically.
  • Lend — Log an advance against a worker's ledger the moment you hand it over, not from memory later.
  • Run — Process payroll for the period and get PDF payslips, without a spreadsheet formula in sight.
  • Resolve — When a worker flags a deduction, the dispute arrives with the record attached — no guesswork.
For the worker

Their own record, without asking the office

  • Check — See this month's attendance and OT as it's marked, not only at month-end.
  • Download — Pull last month's payslip themselves, any time.
  • Ask — Request an advance from inside the app, and see where it stands.
  • Flag — Raise a dispute on a deduction that doesn't look right, and get a real answer.

Period-based processing with configurable wage basis (calendar/fixed-26/fixed-30), OT multiplier, deductions, and PDF payslips.

Before you deploy it

The honest answers, not the polished ones.

Do I need a developer to set this up?

For the first deploy, yes — you're standing up a Postgres database, the Go API (Docker or bare metal), and a free Firebase project for phone-OTP login. Once that's running, day-to-day use — marking attendance, running payroll, approving advances — needs no technical knowledge at all.

What happens if the internet goes down on the shop floor?

Right now, ClearWage needs a connection — it's REST-driven with no local database, and an offline banner tells you when you've lost signal. Offline queuing for attendance is on the roadmap; the database already has a sync_queue table reserved for it, it's just not wired up to the app yet.

Is it actually finished, or still in progress?

Core features — attendance, payroll, ledger, staff management, and reporting — are production-ready and built on battle-tested technologies. The project is under active development, so check the changelog for what's shipped in each release before you commit to a version.

What does it cost to run?

The software itself is free under GPL-3.0. You pay for whatever you host it on — a small Linux server or a Docker host — and Firebase's free tier covers phone-auth OTP for most factories' worker counts.

Can I customize it for my factory's specific rules?

That's the point of it being open source — payroll wage basis, OT multipliers, leave policies, and shift timings are already configurable per tenant in Settings; anything beyond that is a code change away, and the code is yours to change.
